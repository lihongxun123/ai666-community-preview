新手与七日任务
轻引导研发确认页

页面结构不变。任务、奖励、日序和解锁服从后台；C端只负责活动中心锚点气泡与奖励 Toast。

01 不调整页面结构

所有自动引导都锚定顶部活动中心，业务页面和既有弹层保持原结构。

02 后台是任务事实源

任务、奖励、日序、解锁和可参与状态均服从后台活动结果，前端不另建结算规则。

03 一条主线、一次一层

游客注册、新手任务、当天七日任务、其他积分任务依次承接，不同时抢占用户。

04 奖励反馈保持轻量

完成反馈使用无关闭按钮 Toast，约 2.6 秒自动消失，再决定是否出现后续任务气泡。

01 / Logic

业务逻辑

主线优先级已经确认。新手任务未全部完成前，七日任务和其他积分任务不抢占提示；七日任务只提示后台已解锁的当天任务。

主线状态优先级

从左到右读取，命中后停止继续选择

PRIORITY 1 游客注册

未注册时直接用活动中心气泡引导注册。完成注册并自动登录后，第一项新手任务完成。

PRIORITY 2 当前新手任务

按后台结果提示最靠前且可完成的任务，直至 5 项全部完成。

PRIORITY 3 当天七日任务

仅在后台活动已生效、当天日序已解锁时提示 D1—D7 对应任务。

PRIORITY 4 其他积分任务

当前主线暂无可做任务且后台确认仍有其他任务时，引导用户进入活动中心。

七日开启条件：新手任务完成不等于前端立即开启 D1。只有后台返回七日活动已生效且当天任务已解锁，C端才展示对应任务。

页面进入时

  1. 1先判断是否存在登录、发布、评论、生成、兑换等当前业务操作；存在则不覆盖。
  2. 2重新读取注册、新手、七日活动与其他积分任务的最新状态。
  3. 3按主线优先级只选择一个当前可执行任务。
  4. 4游客、未完成新手任务或未完成当天七日任务，刷新后仍继续展示。

任务完成时

  1. 1先根据奖励结果展示“发放中”“已到账”或“结果待确认”的轻 Toast。
  2. 2Toast 每个有效完成事件只出现一次，默认约 2.6 秒自动消失。
  3. 3重新读取下一任务；有可执行任务时再出现活动中心气泡。
  4. 4没有其他可执行任务时结束，不再挂起空气泡。

02 / UX Rules

交互与频率

气泡承担“下一步任务”，Toast 只承担“刚刚发生的结果”。两个载体不混用，同一时刻最多出现一个自动提示。

活动中心锚点气泡

任务引导
新人任务 · 2/5 继续完成第 2 项新人任务 浏览任意一篇 AIGC 作品详情 浏览AIGC作品 · +30 积分
  • 锚定顶部活动中心入口，不改变页面结构。
  • 展示阶段、任务、进度、奖励和行动按钮。
  • 可关闭；关闭只结束当前页面提示，刷新后重新判断。

04 / Acceptance

研发确认与验收

按现有活动能力读取状态并完成以下表现。

需要读取

  • 1注册状态、新手任务当前项及完成结果。
  • 2七日活动是否生效、当前日序及解锁状态。
  • 3任务、进度、奖励、去完成入口及是否还有其他积分任务。

需要实现

  • 1按主线优先级只展示一个自动提示。
  • 2未完成用活动中心气泡，完成结果用奖励 Toast。
  • 3处理刷新重开、事件去重、业务冲突和静默兜底。
✓
任务事实唯一来源

任务、奖励、日序和解锁均来自现有活动结果，不增加 B端配置项。

✓
主线优先级正确

游客注册 → 当前新手任务 → 当天七日任务 → 其他积分任务。

✓
刷新与事件去重

未完成任务刷新后继续提示；同一完成事件的 Toast 不重复。

✓
奖励与结束分支

奖励文案服从结果；没有其他任务时，Toast 消失后结束。

✓
业务操作不被覆盖

登录、发布、评论、生成、兑换等当前业务操作优先于任务轻引导。

✓
移动端与辅助访问

无横向溢出，状态提示使用礼貌播报；减少动态效果偏好得到尊重。
